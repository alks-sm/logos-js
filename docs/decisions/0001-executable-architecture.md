# 0001. Архитектура и планы — исполняемые данные, а не проза в Markdown

**Статус:** принято

## Контекст
При разработке сложных систем с участием нескольких языковых моделей (Claude, DeepSeek и др.) текстовые документы в Markdown работают как «испорченный телефон»: одна модель записывает правило с метафорами и вольными трактовками, другая модель понимает его иначе или отмахивается на ревью («я так не думаю»). Прозу невозможно автоматически скомпилировать или сверить с исходным кодом.

## Решение
1. Все правила, границы слоёв, состояния, протоколы и алгоритмы описываются как **структурированные данные** (`Logos.project`, `Drakon`, `Lanes`).
2. Любая графическая схема в браузере и любой текстовый промпт для ИИ (`Logos.brief`, `Logos.judge`) являются **чистыми проекциями** этой базы данных.
3. Правило без привязанного автоматического стража (`guard` / `rules`) помечается верификатором `Logos.lint()` как незащищённое предупреждение.

## Следствия
* Исключается расхождение между документацией, визуальной схемой и проверками кода.
* Полная модель архитектуры проекта помещается в компактный срез (5–10 КБ), который можно целиком инжектировать в контекст агента через хук или MCP.
