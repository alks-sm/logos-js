# 0005. Проверка до записи (М11): валидация колбэка и схемы перед сохранением

**Статус:** принято

## Контекст
Когда ИИ-агент пишет код напрямую в файлы проекта, невалидный или нечистый код попадает в рабочее дерево, ломает сборку и требует дополнительных итераций отладки.

## Решение
В командном слое `logos-api.js` (команда `checkSlotCandidate` / `logos_check_slot`) реализован принцип **проверки до записи**:
1. Код кандидата-колбэка сначала проверяется регулярными правилами чистоты (`PURITY_RULES`: отсутствие `let`, `var`, `class`, `this`, `window`, `document`).
2. Затем функция компилируется в изолированном контексте и прогоняется по всем проверочным примерам (`cases`) своего контракта из `3-contracts.js` на глубоко замороженных входах (`deepFreeze`).
3. Если нарушено правило чистоты или упал хотя бы один пример, команда возвращает точную причину отказа без изменения файлов на диске.

## Следствия
* В каталог `impl/` физически может попасть только чистая функция, прошедшая 100% контрактных тестов.
